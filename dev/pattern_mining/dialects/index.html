Mining Dialects — def/match/emit + four-way support

The Hyperon Pattern Miner's frequent-pattern core (abstract → support → mark-kept) realized on the MeTTa-IL def/match/emit pipeline surface, with the support operation computed in four agreeing dialects.

The def/match/emit frequent-pattern miner

Candidate patterns are generated by an abstraction pipeline written in the def/match/emit surface (see [MeTTa-IL]; lowered to MM2 exec per §9.2). Each def is a named stage; match binds inputs; emit produces the next stage's facts. Abstraction replaces a position with a _ wildcard (a literal marker — no fresh variable; MORK deduplicates identical candidates):

(def abs-subj () (match (drink $s $o) (emit (cand (drink _ $o)))))
(def abs-obj  () (match (drink $s $o) (emit (cand (drink $s _)))))

mine_frequent(cs, abstract_pipeline, minsup) runs the pipeline, counts each candidate's support (distinct ground matches), and keeps those with support ≥ minsup. On the tutorial "drink" DB at minsup = 2:

(drink Alice _) support=2   (drink Bob _) support=2
(drink _ Coke)  support=2   (drink _ Tea) support=3

(drink Carol _) (support 1) is dropped. Follow-ons (per the tutorial): build-specialization, conjunction expansion (do-conjunct → (and …)), and I-surprisingness ranking.

Support in four dialects (they all agree)

Following §9's "same algorithm, compare dialects" methodology, the support op is computed four ways; all return identical counts on the same data (test_pattern_miner.jl, bench_dialects_and_speedup.jl):

DialectFunctionMechanism
Raw-MeTTa interpreterpattern_support_interp(size-atom (collapse (match &self P P)))
Relational (MeTTa-IL → MM2)pattern_supportstructural trie-dump wildcard match
MORK trie querypattern_support_nativespace_query_multi on the comma-wrapped (, P)
MORK-Miner §2.3 counterprefix_count_supportO(1) read of an in-place prefix counter
(drink $x Coke)       interp=2 scan=2 native=2 counter=- → AGREE
(drink Alice $y)      interp=2 scan=2 native=2 counter=2 → AGREE
(inherit $x American) interp=1 scan=1 native=1 counter=- → AGREE

Note on the MORK trie query

pattern_support_native uses space_query_multi, which requires the pattern comma-wrapped as a (, pattern) conjunction (a bare pattern matches nothing — it processes a (, …) factor list; the convention is in space.rs dump_sexpr). It is correct but O(N) — it iterates rather than prefix-anchoring, so it does not provide the MORK-Miner speedup. That speedup comes from the in-place counter, documented in MORK-Native Miner.
